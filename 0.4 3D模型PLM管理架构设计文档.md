## 一、文档概述

### 1.1 文档目的

本文档依据TOGAF®标准第10版架构开发方法（ADM），从业务架构、数据架构、应用架构和技术架构四个维度，系统阐述基于3D模型的PLM（产品生命周期管理）系统架构设计。TOGAF的四大架构域为PLM架构提供了适当的基线。

PLM作为产品全生命周期管理的核心平台，需要将需求、设计、物料清单（BOM）、变体和配置规则整合到一个受控环境中。本文档聚焦于**3D模型识别、智能报价、BOM管理与BOM中台服务**四大核心能力，构建从设计到制造的完整数字主线。

### 1.2 业务场景

根据业务需求，PLM系统需支撑以下核心场景：

> **场景描述**：基于3D模型实现产品全生命周期管理。
> - **3D识别**：对上传的3D模型进行自动识别与特征提取
> - **报价管理**：基于3D模型识别结果，结合BOM数据实现快速报价
> - **3D看板**：3D模型可视化展示与交互
> - **精识别**：对模型进行精细化特征识别与分类
> - **tag分流**：基于标签规则将模型/任务自动分流至对应处理单元
> - **BOM中台**：提供BOM主数据管理与API服务，支撑下游系统消费

### 1.3 参考标准

- TOGAF®标准第10版
- PLM行业架构最佳实践（OpenBOM等现代PLM架构）
- 企业客户主数据中心架构文档（C-MDM）

## 二、业务架构（Business Architecture）

### 2.1 业务愿景与目标

PLM系统建设的核心目标是：**以3D模型为数据核心，构建从设计识别、成本估算到BOM管理的完整产品数据链，实现设计-工艺-制造业务与数据的有效贯通**。

具体目标包括：
- 实现3D模型的自动识别与特征提取
- 基于模型识别结果生成精准报价
- 建立统一的BOM主数据管理体系
- 通过BOM中台向ERP、MES等下游系统提供标准化BOM数据服务
- 实现产品数据的全生命周期追溯与版本管理

### 2.2 业务能力模型

PLM系统支撑的核心业务能力包括：

| 能力域     | 能力项         | 说明                                                 |
| ---------- | -------------- | ---------------------------------------------------- |
| 3D模型管理 | 模型上传与存储 | 支持多格式3D模型（.stl/.obj/.step/.igs等）上传与管理 |
| 3D模型识别 | 特征提取与分类 | 自动识别几何特征、材料、尺寸等关键属性               |
| 3D模型识别 | 精识别         | 精细化特征识别，提取复杂几何与装配关系               |
| 报价管理   | 智能报价       | 基于识别结果与BOM数据自动计算成本与报价              |
| 报价管理   | 报价单生成     | 生成标准化报价文档                                   |
| BOM管理    | BOM创建与维护  | 从3D模型自动生成EBOM，支持多视图BOM管理              |
| BOM中台    | BOM主数据管理  | 统一BOM主数据存储与版本管理                          |
| BOM中台    | API服务        | 向ERP、MES等系统提供BOM数据服务                      |
| 看板管理   | 3D可视化看板   | 3D模型在线预览与交互                                 |
| 智能分流   | 标签分流引擎   | 基于标签自动分流至对应处理单元                       |

## 三、数据架构（Data Architecture）

### 3.1 数据架构目标

PLM数据架构需定义3D模型数据、BOM主数据、报价数据等核心数据实体的模型、存储方案及数据流向。现代PLM平台采用多租户、云原生、图数据库等架构，以图数据库存储复杂的产品关系，以NoSQL存储灵活的目录和属性，以搜索引擎支持快速检索与索引。

## 四、应用架构（Application Architecture）

### 4.1 应用架构目标

构建功能完整、高内聚低耦合的PLM应用平台。核心设计原则：

- **模块化设计**：按业务能力划分独立功能模块
- **可组合架构**：采用可组合PLM架构，由可互换的构建块组成
- **多格式支持**：支持主流3D模型格式
- **开放集成**：通过标准化API与C-MDM、ERP、MES等系统集成

## 五、技术架构（Technology Architecture）

### 5.1 技术架构原则

- **云原生设计**：采用多租户、微服务架构，支持弹性扩展
- **图数据模型**：使用图数据库存储复杂的产品结构和BOM关系
- **多语言持久化**：根据数据类型选择最优存储方案
- **开放API**：提供REST和GraphQL API，支持灵活集成
- **AI就绪**：在核心数据层支持嵌入向量等AI能力

### 5.2 分层架构设计

现代PLM平台采用分层架构设计，将存储服务、检索引擎、权限控制等模块解耦部署：

│  └──────────────┘  └──────────────┘  └──────────────┘        │
├─────────────────────────────────────────────────────────────────┤

### 5.4 3D模型识别技术方案

| 模型分类     | 深度学习（3D CNN / PointNet） | 自动分类模型类型             |
| 自动打标     | 规则引擎 + AI分类             | 生成技术标签                 |

## 六、与相关系统的集成设计

### 6.1 集成原则

| 原则            | 说明                                        |
| --------------- | ------------------------------------------- |
| 主数据单向引用  | C-MDM为唯一客户数据源，PLM只读消费          |
| BOM中台统一输出 | PLM为BOM主数据唯一源，通过BOM中台向下游分发 |
| 实时优先        | 关键数据变更实时同步                        |
| 异步解耦        | 识别、报价等计算密集型任务异步处理          |

### 6.2 集成架构

| 集成对象 | 集成方式            | 数据流向                       |
| -------- | ------------------- | ------------------------------ |
| C-MDM    | REST API            | 客户主数据 → PLM               |
| CRM      | REST API / 消息队列 | 客户需求 → PLM；报价信息 → CRM |
| ERP      | BOM中台API          | BOM主数据 → ERP                |
| MES      | BOM中台API          | MBOM → MES                     |
| DMS      | REST API            | 需求文档 → 触发PLM模型识别     |

### 6.3 BOM中台API设计

| API                         | 方法 | 说明                         |
| --------------------------- | ---- | ---------------------------- |
| `/api/bom/{bomId}`          | GET  | 查询BOM主数据                |
| `/api/bom/{bomId}/tree`     | GET  | 获取BOM树结构                |
| `/api/bom/{bomId}/versions` | GET  | 查询BOM版本历史              |
| `/api/bom/sync`             | POST | BOM数据同步（推送至ERP/MES） |
| `/api/bom/subscribe`        | POST | 订阅BOM变更通知              |
| `/api/bom/validate`         | POST | BOM数据校验                  |


## 七、安全与权限设计

### 7.1 权限模型

采用RBAC（基于角色的访问控制）模型：

| 角色       | 权限范围                              |
| ---------- | ------------------------------------- |
| 设计工程师 | 上传3D模型、查看识别结果、创建BOM     |
| 成本核算员 | 查看模型与BOM、创建报价、提交审批     |
| 技术主管   | 审核报价、审批BOM、查看全部数据       |
| 销售       | 查看报价（只读）、通过CRM查看关联数据 |
| 采购       | 通过BOM中台获取BOM数据（只读）        |
| 管理员     | 系统配置、用户管理、审计日志          |

### 7.2 安全措施

- **传输加密**：全链路HTTPS加密
- **存储加密**：3D模型文件加密存储
- **操作审计**：上传、识别、报价、BOM变更等关键操作全记录
- **访问控制**：基于角色的细粒度权限控制
- **数据脱敏**：敏感报价数据脱敏展示

## 九、风险与应对

| 风险                           | 影响                  | 应对措施                                  |
| ------------------------------ | --------------------- | ----------------------------------------- |
| 3D模型格式多样，识别准确率不足 | 影响报价与BOM生成精度 | 分阶段提升识别能力，支持人工校验与修正    |
| BOM数据量大，中台性能瓶颈      | 影响下游系统数据消费  | 采用图数据库优化BOM结构查询，缓存热点数据 |
| 与ERP/MES集成复杂              | 数据不一致风险        | 建立BOM中台作为统一数据源，标准化API      |
| 3D模型文件存储成本高           | 成本失控              | 制定存储生命周期策略，冷热分层            |
