## 一、文档概述

### 1.1 文档目的

本文档依据TOGAF®标准第10版架构开发方法（ADM），从业务架构、数据架构、应用架构和技术架构四个维度，系统阐述企业ERP（企业资源计划）系统的架构设计。

TOGAF提供了一个全面、开放的企业架构框架，其四大架构域（BDAT：Business、Data、Application、Technology）为ERP系统的架构设计提供了方法论支撑。本文档聚焦于ERP系统的核心功能——**生产订单管理、物料需求计划（MRP）、生产排产（Scheduling）** ，以及**基于标签（tag）的智能分流机制**。

### 1.2 业务场景

根据业务需求，ERP系统需支撑以下核心场景：

> **场景描述**：报价单审批通过后，生成生产订单进入ERP系统，触发物料预定与排产流程。
> - **订单管理**：从PLM/CRM接收报价单，生成生产订单
> - **物料需求计划（MRP）** ：基于生产订单与BOM，自动运算物料需求
> - **排产管理**：基于产能、设备、人员等约束条件进行生产排程
> - **tag分流**：基于订单标签自动分流至对应的生产线/车间/班组

## 二、业务架构（Business Architecture）

### 2.1 业务愿景与目标

ERP系统建设的核心目标是：**以生产订单为驱动，构建从物料需求计划到生产排产的全链路资源计划体系，实现“接单→计划→采购→生产”的业务闭环**。

具体目标包括：
- 实现生产订单的统一管理与全生命周期跟踪
- 基于MRP算法自动生成物料需求计划
- 基于产能约束自动生成可行的生产排产计划
- 通过tag分流机制实现订单的自动分发与调度
- 与PLM、CRM、MES等系统深度集成，消除信息孤岛

### 2.2 业务能力模型

ERP系统支撑的核心业务能力包括：

| 能力域       | 能力项          | 说明                              |
| ------------ | --------------- | --------------------------------- |
| 生产订单管理 | 订单创建与导入  | 从PLM/CRM接收报价单，生成生产订单 |
| 生产订单管理 | 订单状态跟踪    | 订单全生命周期状态管理            |
| 生产订单管理 | 订单变更管理    | 订单变更申请、审批与执行          |
| 物料需求计划 | MRP运算         | 基于BOM、库存、在途等数据自动运算 |
| 物料需求计划 | 采购计划生成    | 自动生成采购建议与采购订单        |
| 物料需求计划 | 物料齐套检查    | 检查物料齐套性，预警缺料风险      |
| 生产排产     | 产能评估        | 基于设备、班组、工作日历评估产能  |
| 生产排产     | 排程优化        | 基于约束条件自动排产              |
| 生产排产     | 排产调整        | 支持人工干预与调整                |
| 智能分流     | 标签分流引擎    | 基于订单标签自动分流至生产线/车间 |
| 系统集成     | PLM/CRM/MES集成 | 与上下游系统数据互通              |

## 四、应用架构（Application Architecture）

### 4.1 应用架构目标

构建功能完整、高内聚低耦合的ERP应用平台。核心设计原则：

- **模块化设计**：按业务能力划分独立功能模块
- **计划驱动**：以MRP和排产为核心引擎
- **智能分流**：基于标签规则引擎实现订单自动分发
- **开放集成**：通过标准化API与PLM、CRM、MES等系统集成

### 4.4 MRP运算引擎设计

MRP（物料需求计划）是ERP的核心引擎之一，实现从生产需求到物料采购的自动转化：

```
┌─────────────────────────────────────────────────────────────────────┐
│                      MRP运算引擎                                   │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  输入：生产订单 + BOM + 库存数据 + 在途数据 + 安全库存             │
│                    │                                               │
│                    ▼                                               │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  MRP运算流程                                               │   │
│  │  ┌─────────────────────────────────────────────────────┐   │   │
│  │  │ Step 1: BOM展开   → 逐层展开物料清单               │   │   │
│  │  │ Step 2: 净需求计算 → 需求 - 库存 - 在途 + 安全库存  │   │   │
│  │  │ Step 3: 批量规则   → 按最小采购批量/经济批量调整    │   │   │
│  │  │ Step 4: 时间推算   → 基于提前期推算采购/生产时间    │   │   │
│  │  │ Step 5: 建议生成   → 生成采购建议/生产建议         │   │   │
│  │  └─────────────────────────────────────────────────────┘   │   │
│  └─────────────────────────────────────────────────────────────┘   │
│                    │                                               │
│                    ▼                                               │
│  输出：采购建议单 + 生产建议单 + 缺料预警                          │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

## 五、技术架构（Technology Architecture）

### 5.1 技术架构原则

- **高可用性**：ERP为生产核心系统，需保障7×24小时服务可用
- **高性能**：MRP运算涉及大量数据计算，需保障运算性能
- **可扩展性**：支持订单量、物料数据量的线性增长
- **数据一致性**：保障库存、订单等关键数据的强一致性
- **安全性**：生产数据涉及商业机密，需严格权限管控

### 5.4 MRP运算性能设计

MRP运算涉及大量数据（BOM展开、库存扣减、需求计算），需进行性能优化：

| 优化策略 | 说明                                          |
| -------- | --------------------------------------------- |
| 异步运算 | MRP运算作为异步任务，提交后后台执行，避免阻塞 |
| 增量运算 | 仅对变更的订单进行增量MRP运算，而非全量重算   |
| BOM缓存  | 将BOM结构缓存至Redis，减少数据库查询          |
| 批量处理 | 批量订单合并运算，减少运算次数                |
| 分片计算 | 大数据量时按物料分组分片并行计算              |

## 六、与相关系统的集成设计

### 6.1 集成原则

| CRM      | REST API            | 订单生产进度 → CRM（客户360视图） |
| MES      | REST API / 消息队列 | 排产计划 → MES；生产进度 ← MES    |
| 采购系统 | REST API            | 采购建议 → 采购系统               |
| C-MDM    | REST API            | 客户主数据 → ERP                  |

## 七、安全与权限设计

### 7.1 权限模型

采用RBAC（基于角色的访问控制）模型：

| 角色       | 权限范围                                 |
| ---------- | ---------------------------------------- |
| 计划员     | 创建/修改生产订单、运行MRP、制定排产计划 |
| 采购员     | 查看MRP结果、创建采购订单                |
| 生产主管   | 查看排产计划、调整排产、查看生产进度     |
| 车间操作员 | 查看工单、报工（通过MES）                |
| 管理层     | 查看生产报表、订单进度（只读）           |
| 管理员     | 系统配置、用户管理、审计日志             |

### 7.2 安全措施

- **传输加密**：全链路HTTPS加密
- **存储加密**：敏感数据加密存储
- **操作审计**：订单创建、MRP运算、排产调整等关键操作全记录
- **访问控制**：基于角色的细粒度权限控制

## 九、风险与应对

| 风险                         | 影响               | 应对措施                           |
| ---------------------------- | ------------------ | ---------------------------------- |
| BOM数据不准确导致MRP运算错误 | 采购错误、生产延误 | 建立BOM数据校验机制，与PLM保持同步 |
| MRP运算性能瓶颈              | 影响计划效率       | 异步运算、增量计算、缓存优化       |
| 排产与实际产能偏差           | 计划不可执行       | 建立产能反馈机制，支持人工调整     |
| 与MES集成延迟                | 生产进度无法反馈   | 设计降级方案，支持手工报工         |
| 数据一致性风险               | 库存数据不准确     | 事务管理、数据校验、定期对账       |
